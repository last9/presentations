Required baseline

What is an agent?

An LLM in a loop that takes actions, keeps state, and acts in the world, not a chatbot, not RPA.

the payoff An agent isn't an "AI feature." It's a code-execution system.

Whose code is it, anyway?

🤖 LLM-generated

The model writes a command, a query, a script, at runtime, unreviewed.

📦 Third-party skills

Installed from a registry. You didn't write it; you can't fully audit it.

👤 Customer-authored

Tenants bring their own skills onto your shared platform.

The code's origin changed: written at runtime, prompt-injected from a webhook. One sentence now does what used to take a supply-chain compromise.

The comfortable illusion

"We'll add guardrails to the prompt."

A prompt is an instruction; it runs before the model misbehaves. A tool call is a syscall; once code runs, your prompt is a suggestion.

Chipotle's support bot was jailbroken into writing code. The takeaway (Opus Research): "enforce scope at the product level, not just in the prompt."

you can't contain a running process with English.

The seductive wrong answer: "we'll just put guardrails in the system prompt." A prompt is an instruction that runs before the model decides to misbehave; a tool call is a syscall, and once code is running the prompt is a suggestion. Concrete proof: Chipotle's bot got talked into writing code, scope creep, and the analyst's takeaway is literally our thesis: enforce scope at the product level, not just the prompt. Transition: so where did we start? Honestly, with no isolation at all.

THE ONE IDEA

Isolation must be structural, not conventional.

Enforced by the layer below the agent: the crypto, the database key, the kernel. The most structural boundary of all is a kernel the agent doesn't share.

the test: does it make the attack impossible, or just tedious?

This is the whole talk in one line. Say it slowly. Structural means the guarantee lives BELOW the agent, in a layer the agent can't reach: the crypto, the DB key, the kernel. Conventional means a rule in the agent's own code that we hope it follows. Then give them the test they can take home, the one Anthropic's zero-trust framework uses: does this control make the attack IMPOSSIBLE, or just TEDIOUS? A rate limit is tedious. A separate kernel is impossible. Prefer removing a capability over throttling it. Transition: let's watch a hostile agent try five things, and judge each defense by that test.

Attack 1 · secret theft

"I'll read the other tenant's API keys."

engineer9 for Acme holds Acme's AWS key. The instance for Globex shares the same process pool and one Postgres. One SELECT away?

Structural control · the credential store

Bound to one agent at construction.


// Cross-agent access is structurally impossible, workspace_id and
// agent_id are bound at construction; the key is derived from them.
func NewPGStore(pool, masterKey, workspaceID, agentID) (Store, error)

SELECT encrypted_value FROM credentials
 WHERE workspace_id = $1 AND agent_id = $2 AND name = $3

Per-credential Argon2id → AES-256-GCM. You can't name another agent's secret.

✓ contained, by the database key, not by careful code
Attack 2 · sandbox escape

"I'll write a binary and run it."

The agent can write files in its working dir. So it drops an ELF and execs it , now it's arbitrary native code, off the rails.

Structural control · Landlock LSM (kernel)

Writable, but not executable.


AccessReadWrite    // agent's own dir: create/modify files…
                   // …but the exec bit is withheld
AccessReadExecute  // system paths only: /usr, /lib
// /proc/self only, can't read /proc/<pid>/environ of neighbours

A sandbox-launcher applies Landlock, then execs the agent. The kernel refuses the exec regardless of what the code does.

✓ contained, the LSM doesn't care how clever the code is

but it's still a shared kernel. hold that thought, we'll hit its ceiling.

Attack 3 · runaway process & an honest gap

"I'll fork forever / never return."

What we do

One OS process group per agent (Setpgid). Stop = hierarchical SIGTERM→SIGKILL of the whole tree. A crash is confined.

What we don't (yet)

No per-agent CPU/memory cgroups v2 quota. A tight loop can still hog a core , and that motivates the last act.

Attack 4 · runaway spend

"I'll burn $50k in a retry loop."

An agent stuck in a tool-error loop can spend more in an hour than your team spends in a month. Token spend is the new blast radius.

Structural control · pre-call budget gate

Check the budget before the call.


func BudgetCheck(ctx, pool, workspaceID) (*Budget, error) {
    if hardCap != nil && totalCost >= *hardCap {
        return &budget, ErrHardCapExceeded   // block the call
    }
    if softCap != nil && totalCost >= *softCap {
        return &budget, ErrSoftCapExceeded   // downgrade Opus → Haiku
    }
}

Atomic per-(workspace, agent, model) counters, in micro-USD integers.

⛔ blocked before a single token is spent
Attack 5 · supply chain

"I'll push malicious code through your deploy."

Skills ship via git webhook. Spoof it, smuggle a ../ path or a symlink, plant a setuid binary, own the box through the pipeline.

Structural control · every push is treated as hostile

✓ HMAC-SHA256 verify + 5-min replay window

✓ reject ../ traversal & symlinks

✓ strip setuid/setgid: mode & 0755

✓ size / file-count caps (no zip-bombs)

atomic + reversible

Deploy writes a new version dir, then flips a symlink. It fully lands or nothing changes. Rollback is one more flip.

✓ contained, verified, sandboxed, reversible
The cross-cutting layer

Every attempt is on the record, tamper-evidently.


// per-workspace SHA-256 hash chain: each event hashes the one before
data := fmt.Sprintf("%s|%s|%s|%s|%s|%s",
    prev, evt.Timestamp, evt.EventType,
    evt.WorkspaceID, evt.AgentID, evt.RequestID)
hash := sha256.Sum256([]byte(data))   // tamper one row → chain breaks

Append-only, batched, date-partitioned. "What did it do, and can I prove it?", yes.

"Why not just a container?"

A container shares the host kernel.

Namespaces change what a process sees. They don't change what the kernel does.

457 syscalls reachable from a
container (Docker blocks ~49) → ~25 KVM hypercalls to a
separate-kernel micro-VM

process→ container→ LSM · us today→ micro-VM→ confidential VM→ bare metal

runc escapes land yearly. AWS: "we don't consider containers a security boundary."

Where the boundary actually is

The one that holds doesn't share a kernel.

✓ a separate kernel per tenant, no shared escape surface

✓ clean CPU/mem/disk quotas (our cgroups gap, gone)

✓ a unit for data residency, the VM lives in the customer's cloud

Firecracker: ~125ms boot, 4ms restore, zero host escapes since 2018.

The industry converged here: e2b, Modal, Fly, Lambda, now Apple & Microsoft.

Landlock hit the shared-kernel ceiling. A separate kernel is the next layer, and you can buy it.

The honest pivot. Landlock was real work and it holds against a lot, but it is hardening a kernel the agent still shares. The ceiling is the kernel itself. Apply the test: a separate kernel makes escape impossible, not tedious. The good news for the audience: you don't have to build this.
