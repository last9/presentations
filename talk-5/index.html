Required baseline

What is an agent?

An LLM in a loop that takes actions, keeps state, and acts in the world, not a chatbot, not RPA.

its code keeps changing New skills ship constantly, often via git webhook from sources you don't fully control.
THE ONE IDEA

Treat every push as hostile until verified.

A deploy pipeline is an entry point. Authenticate it, sanitize it, and make it atomic, so a bad deploy can't half-land.

The pipeline is the attack surface

Supply chain is where agents get popped.

30+ MCP CVEs in 60 days. A poisoned npm package via prompt-injection: ~4,000 installs in 8 hours.

Spoof the webhook, smuggle a ../ path or a symlink, plant a setuid binary, and you own the box through the front door.

Structural control · verify, then sanitize

Five doors, five locks.

✓ HMAC-SHA256 verify (GitHub/GitLab/generic)

✓ 5-minute replay-dedup window

✓ reject ../ traversal & symlinks/hardlinks

✓ strip setuid/setgid: mode & 0755

✓ size / file-count caps (no zip-bombs)

✓ optional source-IP allowlist

✓ a bad signature never reaches extraction; a bad path never reaches disk
Structural control · atomic + reversible

All-or-nothing, with instant rollback.


agents/<id>/versions/v42/     # new version written in full
agents/<id>/current -> v42    # one atomic symlink swap flips it live
# rollback = flip the symlink back to v41. no half-deployed state.

A crash mid-deploy leaves the live symlink untouched. The agent never runs a half-written skill.
