THE ONE IDEA

Isolation must be structural, not conventional.

Enforced by the layer below the agent: the crypto, the database key, the kernel. The most structural boundary of all is a kernel the agent doesn't share.

the test: does it make the attack impossible, or just tedious?

This is the whole talk in one line. Say it slowly. Structural means the guarantee lives BELOW the agent, in a layer the agent can't reach: the crypto, the DB key, the kernel. Conventional means a rule in the agent's own code that we hope it follows. Then give them the test they can take home, the one Anthropic's zero-trust framework uses: does this control make the attack IMPOSSIBLE, or just TEDIOUS? A rate limit is tedious. A separate kernel is impossible. Prefer removing a capability over throttling it. Transition: let's watch a hostile agent try six things, and judge each defense by that test.

Structural control · the credential store

Encrypted to one identity.


// Cross-agent access is structurally impossible, workspace_id and
// agent_id are bound at construction; the key is derived from them.
func NewPGStore(pool, masterKey, workspaceID, agentID) (Store, error)

SELECT encrypted_value FROM credentials
 WHERE workspace_id = $1 AND agent_id = $2 AND name = $3

Per-credential Argon2id → AES-256-GCM, bound to (workspace, agent) at construction — reach the store all you want, it's ciphertext you can't name or decrypt. The sandbox blocks reading a neighbor's env or memory.

✓ a secret it wasn't given is ciphertext it can't read
The structural answer: every secret is encrypted to one identity — Argon2id→AES-256-GCM, bound to (workspace, agent) at construction. Reach the store all you want, it's ciphertext you can't even NAME, let alone decrypt; and the sandbox stops it reading a neighbor's env or memory. Apply the test: this removes the capability — impossible, not tedious. Transition: next, it stops reading and starts running.
Attack 2 · sandbox escape

"I'll run my own program."

The agent can write files in its working dir. So it drops an ELF and execs it — now it's running arbitrary native code.

It can write to its own dir, so it drops a native binary and execs it — now it's arbitrary machine code, outside whatever language runtime we thought we'd sandboxed. Flip to the defense.
Structural control · Landlock LSM (kernel)

Writable, but not executable.


AccessReadWrite    // agent's own dir: create/modify files…
                   // …but the exec bit is withheld
AccessReadExecute  // system paths only: /usr, /lib
// /proc/self only, can't read /proc/<pid>/environ of neighbours

A sandbox-launcher applies Landlock, then execs the agent. The kernel refuses the exec regardless of what the code does.

✓ contained, the LSM doesn't care how clever the code is

but it's still a shared kernel. hold that thought, we'll hit its ceiling.

Landlock — a kernel LSM. The agent's dir is writable but NOT executable; system paths are read-exec only; it sees /proc/self, not its neighbors. A launcher applies Landlock, then execs the agent — the kernel refuses the exec no matter how clever the code is. THE honest beat: plant the flag — "but it's still a shared kernel." We hit that ceiling at the end of the talk.

Runaway compute — a different resource from spend. A bug or a hostile loop forks without end, or just never returns. On shared hardware that starves every other tenant: the noisy neighbor. Flip.
Structural control · process-group isolation

One process group per agent.

Each agent runs as its own OS process group (Setpgid). Stop is a hierarchical SIGTERM→SIGKILL of the whole tree — the runaway and every child it spawned die together.

✓ the runaway and all its children die together, inside one agent
Each agent is its own OS process group (Setpgid). Stop is a hierarchical SIGTERM→SIGKILL of the whole tree — the runaway and every child it spawned die together. A crash or fork storm stays inside one agent. If asked about hard CPU/mem quotas: that's the separate-kernel/microVM layer at the end.

Structural control · pre-call budget gate

Check the budget before the call.


func BudgetCheck(ctx, pool, workspaceID) (*Budget, error) {
    if hardCap != nil && totalCost >= *hardCap {
        return &budget, ErrHardCapExceeded   // block the call
    }
    if softCap != nil && totalCost >= *softCap {
        return &budget, ErrSoftCapExceeded   // downgrade Opus → Haiku
    }
}

Atomic per-(workspace, agent, model) counters, in micro-USD integers.

⛔ blocked before a single token is spent
Check the budget BEFORE the call. Hard cap blocks; soft cap downgrades the model (Opus→Haiku). Atomic per-(workspace, agent, model) counters in micro-USD integers — no float drift. Blocked before a single token is spent. The test: a hard cap removes overspend; a rate limit only slows it.
Attack 5 · supply chain

"I'll slip bad code in through your deploy."

Skills ship via a git webhook — so the attacker poisons the pipeline before the agent ever runs: spoof the webhook, smuggle a ../ path or a symlink, plant a setuid binary.

Different stage — ingress, not runtime. Skills ship via a git webhook, so the attacker poisons the pipeline BEFORE the agent ever runs: spoof the webhook, smuggle a ../ path or a symlink, plant a setuid binary. Flip to the defense.
Structural control · every push is treated as hostile

✓ HMAC-SHA256 verify + 5-min replay window

✓ reject ../ traversal & symlinks

✓ strip setuid/setgid: mode & 0755

✓ size / file-count caps (no zip-bombs)

atomic + reversible

Deploy writes a new version dir, then flips a symlink. It fully lands or nothing changes. Rollback is one more flip.

✓ contained, verified, sandboxed, reversible
Treat every push as hostile: HMAC-verify the webhook, reject ../ traversal and symlinks, strip setuid/setgid (mode & 0755), cap size and file count. And the deploy is atomic — write a new version dir, flip a symlink; it fully lands or nothing changes, and rollback is one more flip. Verified, sandboxed, reversible.

The subtle one — the confused deputy. The agent isn't hacked, it's CONVINCED. A poisoned email, page, or ticket injects an instruction and it acts with its OWN authority. Call back to the open: this is exactly the Meta bot. Flip to the defense.
Structural control · least agency

It can only do what it was granted.

Every skill declares its tools and credentials up front. Sensitive actions are deny-by-default — they need explicit approval, never the agent's own judgment. A hijacked agent still can't invoke a capability it was never given.

✓ injection changes what it wants, not what it can do
You can't fully stop injection — so don't fight that battle. Constrain what it CAN do. Every skill declares its tools and credentials up front; sensitive actions are deny-by-default, needing explicit approval, never the agent's own judgment. A hijacked agent still can't invoke a capability it was never given. Injection changes what it WANTS, not what it CAN do — that's OWASP "least agency." "Why not just a container?"

A container shares the host kernel.

Namespaces change what a process sees. They don't change what the kernel does.

457 syscalls reachable from a
container (Docker blocks ~49) → ~5 emulated devices in a
separate-kernel micro-VM

process→ container→ LSM · us today→ micro-VM→ confidential VM→ bare metal

runc escapes land yearly — CVE-2019-5736 → the Nov-2025 trio. AWS: "does not consider a container … a security boundary."

The objection everyone has. Namespaces change what a process SEES, not what the kernel DOES. ~457 syscalls reachable from a container (Docker's default seccomp blocks ~49); a separate-kernel microVM exposes ~5 emulated devices. runc escapes land yearly — CVE-2019-5736 through the Nov-2025 trio — and AWS's own advisory says it does not consider a container a security boundary. That Landlock ceiling I flagged earlier? This is it. Transition: so what actually holds?
Where the boundary actually is

The one that holds doesn't share a kernel.

✓ a separate kernel per tenant, no shared escape surface

✓ clean per-VM CPU/mem/disk quotas, enforced by the hypervisor

✓ a unit for data residency, the VM lives in the customer's cloud

Firecracker: ~125ms boot, single-digit-ms restore. No confirmed guest→host escape in production.

Converged here: AWS Lambda, e2b, Fly — now Apple & Microsoft.

Landlock hit the shared-kernel ceiling. Anthropic runs Claude Code itself on Firecracker — and you can buy the same thing.

The honest pivot. Landlock was real work and it holds against a lot, but it is hardening a kernel the agent still shares. The ceiling is the kernel itself.
