Required baseline

What is an agent?

An LLM in a loop that takes actions, keeps state, and acts in the world, not a chatbot, not RPA.

it acts on your behalf Every tool call is an action someone will later ask you to account for.
THE ONE IDEA

Make the record tamper-evident, not merely trusted.

A log you can edit isn't evidence. A hash chain turns "trust the log" into "verify the log."

The question you'll be asked

"What did the agent do, and can you prove it?"

engineer9 stopped an EC2 instance and posted to a customer channel. Six months later, compliance wants the trail.

If the trail lives in a mutable table the same operators can edit, it isn't proof.

Structural control · per-workspace hash chain

Each event hashes the one before it.


data := fmt.Sprintf("%s|%s|%s|%s|%s|%s",
    prev, evt.Timestamp, evt.EventType,
    evt.WorkspaceID, evt.AgentID, evt.RequestID)
hash := sha256.Sum256([]byte(data))   // becomes prev for the next event

Append-only, batched (100 / max 1s), date-partitioned. Tamper with one row and every subsequent hash stops matching.

✓ provable, the chain breaks where the edit happened

this is the zero-trust Enterprise bar: "immutable audit trails with integrity verification."

Observability without melting Prometheus

The cardinality trap.

The obvious mistake

Label every metric with workspace_id. 10,000 tenants × every series = a cardinality explosion that takes down your metrics backend.

What we do

12 metrics (LLM, tools, approvals, cost, audit health). High-cardinality IDs go in exemplars (request_id), not labels.

Drill from a metric to a trace by exemplar, without paying the cardinality tax.

DEMO

Edit one audit row. Watch the chain break.

UPDATE a single detail field in Postgres, re-walk the chain, and the verifier points straight at the tampered row.
